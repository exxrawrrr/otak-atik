# Product Principles

1. **Capability over vendor** — skills depend on generic capabilities, not provider-specific tool names.
2. **Least privilege first** — broad access is opt-in.
3. **Skills load on demand** — context is a resource.
4. **Tools and skills are different** — hands are not instructions.
5. **Verification follows mutation** — "command exited" is not proof of success.
6. **Local-first where practical** — configuration and operator state belong with the user.
7. **Inspectable over magical** — automation must be explainable.
8. **Recoverable over clever** — retries, dry-runs, and checkpoints beat hidden heroics.
9. **No fake certainty** — an unavailable capability is reported, not hallucinated.
10. **Public core, private overlay** — personal data and private workflows do not belong in public core.
