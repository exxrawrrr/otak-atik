# Research status

otak-atik is an **active public experiment**.

It is not a finished product pretending to know its final architecture.

## Current certainty

High confidence:

- provider-neutral capabilities are useful;
- local work should prefer local MCP;
- genuinely remote work benefits from remote MCP;
- skills should load selectively;
- mutation needs verification;
- failed experiments should be recorded.

Still evolving:

- adapter runtime;
- recipe execution;
- audit ledger;
- checkpoint/rollback model;
- GUI-control provider strategy;
- cross-client compatibility;
- packaging/distribution;
- how autonomous the operator layer should become.

## Possible futures

The repo may evolve into one or more of:

- an operator CLI;
- a portable Agent Skills runtime;
- an MCP transport router;
- a verification/evidence layer;
- a provider benchmark suite;
- a local control plane;
- something else learned from real usage.

The roadmap is directional, not prophecy.

## Project rule

When real-world evidence contradicts the architecture, update the architecture.

Do not protect yesterday's diagram from today's result.
